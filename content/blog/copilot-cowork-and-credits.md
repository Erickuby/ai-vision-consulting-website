# Copilot Cowork and credits: check the task, cost and controls

Start with one task you can describe and check. A reporting pack, briefing or meeting follow-up may be worth a pilot when you have approved sources and a clear definition of a useful result. Treat the output as work to review before anybody relies on it.

## Quick answer

Cowork can help with multi-step work across approved Microsoft 365 sources and tools. Check the features available to your account and define checkpoints before anything is shared or changed. A task that completes still needs a person to check its accuracy and suitability.

Microsoft uses Copilot Credits for usage-based experiences alongside fixed licensing. There is no universal price for a task. Check your organisation's access, applicable licence and current credit rates, then measure a small pilot instead of relying on an assumed cheap run.

Administrators can manage usage and spending policies through the Microsoft 365 admin centre. Spending safeguards and access controls need separate attention: credit-limit enforcement can be delayed. [Read Microsoft's billing guidance](https://learn.microsoft.com/en-us/microsoft-365/copilot/usage-based-billing-manage-copilot-credits).

## Key takeaways

- Cowork output needs review even when the task reports completion.
- It works across apps and data, not inside a single file.
- Usage-based charges can sit alongside fixed licensing.
- Check the actual usage of a bounded task before estimating repeat costs.
- Set budgets and monitor the dashboard from day one, not after the first invoice.
- Include checking and correction time when comparing the cost with manual work.
- Anything with a legal, financial or customer consequence still needs a human sign off.

## What Cowork actually does

### The difference from Agent Mode

Agent Mode in Word, Excel and PowerPoint works inside the file you have open. Cowork operates a level above that. It handles work that crosses boundaries: reading a thread of emails, pulling figures from a spreadsheet, drafting a document and assembling a deck, as one continuous piece of work with a deliverable at the end.

The practical test is whether the task involves several applications and dependent steps. If it is one document and one goal, start by checking the in-app features you already have. Compare cost and effort in your own account rather than assuming one route is always cheaper or faster.

### The kind of task it suits

Consider a reporting pack assembled from approved correspondence and performance data, or a project summary drawn from meeting material. These still involve judgement: deciding which evidence matters, checking calculations and confirming owners and deadlines.

Choose a task with clear inputs and an output you can assess. That gives you a fair test of whether the assistance is useful.

### The kind of task it does not suit

Avoid a broad request without a clear result. It can consume usage and still answer the wrong question. Agree what finished means before starting.

Also avoid it for work with a genuine judgement core: deciding a strategy, handling a sensitive personnel matter, choosing between two commercial options. It can assemble the evidence for those. It should not be making the call.

## How the money works

The work performed and applicable billing rules determine usage. Use the following as a planning checklist, then check the actual credit record rather than treating it as a price formula.

| Cost driver | What increases it | How to keep it down |
| --- | --- | --- |
| Model use | Longer, more complex reasoning | Scope the task tightly |
| Context retrieval | Searching wide across mail and files | Point it at specific sources |
| Tool calls | Many separate actions and apps | Break huge tasks into defined pieces |
| Runtime | Long running, open ended work | Define what finished looks like |

Name the sources and expected format so the result can be checked. A tighter brief is useful, but it does not guarantee a particular reduction in cost.

### Working out whether it is worth it

The arithmetic is refreshingly simple. Take the task, estimate the staff time it currently consumes, and apply a realistic hourly cost. Compare that with the credit cost of the run plus the time someone spends reviewing the output.

Record preparation, run time, review and correction. A shorter drafting stage is not a saving if checking takes longer or an error creates more work downstream. Keep failed runs in the comparison as well as successful ones.

Run that sum for three or four candidate tasks before you commit to anything. It filters out most of the ideas that sound impressive and save nothing.

## Monitor spending and control access

**Set spending policies before the pilot.** Check who is in scope and which services each policy selects. A very low credit limit still grants access when the policy includes the user and selects Cowork. Limits are evaluated asynchronously, so they are not an immediate hard stop. [Microsoft explains the access rules](https://learn.microsoft.com/en-us/microsoft-365/copilot/cowork/cowork-access).

**Name who can run Cowork tasks.** Usage based billing plus unrestricted access is how organisations get surprised. Start with a small group who understand the cost model.

**Log what you run and what it cost.** The /cost command shows approximate credits consumed so far and information about your monthly limit. It cannot quote the cost in advance and is not an authoritative billing record. Use the organisation's billing records to reconcile charges. [Read the /cost guidance](https://learn.microsoft.com/en-us/microsoft-365/copilot/usage-based-billing-copilot-credits-cost).

**Review the first outputs closely.** Early on, the review is not only quality control. It is how you learn to specify tasks well, which is the main lever on cost.

**Revisit anything that runs repeatedly.** A task you run weekly is worth spending an hour refining. Small improvements to a recurring request compound.

## Where this sits in a sensible AI plan

Cowork is not the starting point. Organisations that get value from it have usually already done the unglamorous work: their people know how to use Copilot properly, their SharePoint permissions are not a liability, and they have identified which recurring tasks are genuinely worth automating.

Buying agentic capability before any of that is in place is the same mistake as buying Copilot licences and hoping adoption happens by itself. The tool is capable. The value comes from knowing precisely what you want it to do.

## Frequently asked questions

### Is Cowork included in a Microsoft 365 Copilot licence?

Check your organisation's applicable licence and usage-based billing configuration. Owning a Copilot licence does not establish that every Cowork task is included without further charges.

### What does a typical task actually cost?

There is no reliable single price for every task. Measure a bounded pilot and check the current rates and billing arrangement. The /cost command reports approximate usage already incurred, not a price before you start.

### Can we cap what a team spends?

Administrators can set spending safeguards, but consumption and limit enforcement can lag. Use policy scope to control access and monitor actual consumption. Do not treat a credit limit as a real-time access gate.

### How is this different from building an automation in Power Automate?

A conventional workflow follows defined triggers and steps; AI-assisted work can handle variation but needs careful review. For a stable process, compare a rule-based automation as part of the options. Cost and reliability depend on the actual design, licences and maintenance.

### Should a small business be looking at this yet?

Only if there is a specific recurring task with real hours attached to it. For most small organisations the larger and cheaper win is still training people to use the Copilot they already have, and cleaning up the data it reads.
